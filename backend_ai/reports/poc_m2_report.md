## 二、关键结论

### ✅ SwingNet 在"干净单次挥杆"上显著优于规则引擎

前 3 段（用户真实上传/微信传输的干净视频）：

| 指标 | SwingNet | 规则引擎 |
|---|---|---|
| 平均击球帧误差 | **≈1 帧** | **≈2.7 帧** |
| 完全命中（0 误差）| 2/3 | 0/3 |
| Impact 置信度 | 0.68~0.96（高）| —（无置信度概念）|

**最有力的证据**：4e8d0d7e 的击球帧，规则引擎反复调都偏 +5 帧（今天一整天的痛点），SwingNet 直接 0 误差命中（conf 0.96）。

### ⚠️ SwingNet 的适用边界：必须"单次挥杆"

后 3 段（历史样本库，视频本身有问题）SwingNet 退化（时序乱、置信度低）：
- 这与 GolfDB 论文的前提一致——"**trimmed videos containing a single swing**"（裁剪到单次挥杆的视频）
- c6f67f38 之前已被诊断为"视频被剪辑过"
- 470057ac / f470c599 疑似含多次挥杆/挥杆前后大量无关内容

**结论**：SwingNet 需要"挥杆窗口裁剪"前置——而主 backend 的规则引擎恰好能定位挥杆窗口（Address→Finish），两者是**互补**而非竞争。

## 三、最终 POC 结论

> **AI 路线可行 ✅**：在用户真实上传场景（单次挥杆）下，SwingNet 把 DTL 击球帧误差从规则引擎的 ±5 帧收窄到 ≈1 帧。

**但前提**：
1. 需要"挥杆窗口裁剪"前置（复用主 backend 的规则引擎）
2. 商用需解决 CC BY-NC 非商业许可（换 CaddieSet / 自采标注 / 授权）
