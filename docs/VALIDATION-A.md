## 1. 概述

本项目（微信小程序 + Python 后端的高尔夫挥杆姿态分析工具）此前从未用真实视频验证过。本次首次拿到 **11 段**真实视频（3 段正面 face-on + 6 段侧面 DTL + 2 段 `video/` 目录下补充样本），目标是：

1. 跑通 `backend/run.py check` 与对 11 段视频逐一 `segment` 的完整 pipeline；
2. 走完整 pipeline 跑正面 3 段，取得每阶段完整指标数值；
3. **核对指标符号与量纲**：顶点 Top 的 `shoulder_turn` 应为正；X-Factor = 肩转角 − 髋转角，业余 20~35°、职业 42~50°，若 >90° 或负得很大说明公式/参考系有问题；
4. 若切分阈值不适配真实视频则调整并说明依据；若符号/公式错误则修复 `metrics.py`/`geometry.py` 并同步单元测试；
5. 跑 `pytest` 确认无回归；
6. **验收标准：切分成功率 ≥ 70%**。

### 5.1 顶点 Top 的 `shoulder_turn` 必须为正

| 正面2 | **+39.1°** | -39.1° | ✅ 正，符号正确 |
| 正面3 | **+27.1°** | -27.1° | ✅ 正，符号正确 |
| DTL-0bb16a97 | +15.1° | -15.1° | ✅ 正 |
| DTL-470057ac | +95.4° | -95.4° | ✅ 正（DTL 朝向耦合偏大，但符号正确） |
| DTL-4e8d0d7e | +76.8° | -76.8° | ✅ 正 |

### 5.2 X-Factor = 肩转角 − 髋转角

X-Factor 公式路径：`metrics._shoulder_turn_at` / `_hip_turn_at` → `geometry.rotation_xz`（内含 `ROTATION_SIGN`）→ `_x_factor_at = shoulder − hip`。

| 视频 | Top `shoulder_turn` | Top `hip_turn` | X-Factor | 判定 |
|------|-------------------|---------------|----------|------|
| 正面1 | 66.4° | 17.0° | **49.5°** | 业余/职业交界，合理 |
| 正面2 | 39.1° | 10.7° | **28.4°** | 落在业余 20~35° 带 ✅ |
| 正面3 | 27.1° | 6.4° | **20.7°** | 落在业余 20~35° 带 ✅ |
| DTL-470057ac | 95.4° | 27.9° | 67.5° | DTL 朝向耦合偏大（见 §7） |
| DTL-4e8d0d7e | 76.8° | 36.9° | 39.9° | 合理 |
| DTL-c6f67f38 | 79.8° | 40.9° | 38.9° | 合理 |

**判定**：正面 3 段 X-Factor 全部落在 20~50° 合理区间，**无 >90°、无巨大负值**，公式与参考系正确。DTL 视频因侧面机位下肩宽被投影压缩、且与正面机位朝向耦合，X-Factor 偏大（如 470057ac=67.5°），但符号与公式一致，属机位限制而非 bug。

### 5.3 `metrics.py` / `geometry.py` 是否需要改

**结论：无需修改。** 符号路径与量纲经 11 段视频全部验证正确：
- `geometry.rotation_xz` 返回 `degrees(atan2(cross, dot)) * ROTATION_SIGN`，`ROTATION_SIGN=-1` 经验证正确；
- `_x_factor_at = shoulder − hip` 公式正确；
- 因此**未改动** `metrics.py`/`geometry.py`，也**无需同步修改任何单元测试**（既有 220 个测试全部通过）。

## 6. 问题清单（真实视频暴露的根因）

真实视频暴露了 4 类此前合成数据未能发现的问题，按严重度：

| # | 问题 | 根因 | 影响 | 处理 |
|---|------|------|------|------|
| P1 | 各向异性阈值漂移 | `norm` 的 x/y 单位不同（x=W 像素、y=H 像素），竖屏 720×1280 与横屏 1280×720 间阈值实际漂移 1.78²≈3.2 倍 | 竖屏 travel_in_S≈1.9~2.6、横屏≈3.1，阈值口径混乱 | `build_signals` 引入 `aspect=H/W` 拉伸 y，阈值整体 ×1.78 重算 |
| P2 | 绝对 `wrist_y` 受人体平移污染 | `locate_top` 用绝对图像纵坐标，球手全程缓慢下移时站位 `wrist_y` 反而比顶点更"高" | DTL-0bb16a97 误判顶点→假 `NO_SWING` | `locate_top`/`locate_impact` 改用髋部相对高度 `h` |
| P3 | Impact 搜索区间无上界 | `locate_impact` 全区间找高度回落，顶点后长期举杆时回落点在 95 帧后 | DTL-470057ac 算出 3.17s 假下杆 | 加 `MAX_DOWNSWING_SEC` 上界；无穿越回退速度峰 |
| P4 | `MIN_TOP_ADDR_SEC` 过紧 | 0.15s 远小于真实上杆 0.8~3.63s | 残缺视频被切成 8 个挤在 0.2s 的垃圾阶段（087d40a0/707fb04a） | 放宽到 0.45s，让残缺视频诚实 `NO_SWING` |
| P5 | 顶点前减速微停误判为 Address | `V_STILL=0.55` 把顶点附近手腕瞬时变慢（h≈2）当成一段静止 | 正面2 的 Address→Top 被挤压成 1 帧→假 `NO_SWING` | `locate_address` 增加 `ADDR_H_MAX` 高度上限过滤 |
| P6 | `LOW_QUALITY` 阈值过严 | `MISS_RATIO_LOW_QUALITY=0.10` 把 87% 检出率的可用视频误杀 | DTL-4e8d0d7e 被拒 | 放宽到 0.15（仍 >15% 漏检提示、>50% 硬失败） |

## 7. 修改文件与依据

### 7.1 `backend/app/segmenter.py`

- **`build_signals(frames, fps, aspect=1.0)`**：新增 `aspect` 参数，对 `norm` 的 y 轴乘 `ratio=H/W`，使 x/y 同为「图像宽度」单位（各向同性）。修复 P1。调用方（`pipeline.py`、`_cli`、探针）均传入 `meta.height/meta.width`。
- **`locate_top`**：顶点判据由 `argmin(wrist_y)` 改为 `argmax(h)`（髋部相对高度，天然抵消人体平移，修复 P2）；并用全局速度峰收窄搜索上界，防止顶点误判到收杆。
- **`locate_address`**：候选静止段增加末帧手位高度过滤 `h[end] <= ADDR_H_MAX`（默认 0.6），排除顶点前减速微停造成的高点假静止（修复 P5）。
- **`locate_impact`**：搜索区间上限 `hi = min(n, i_top+1+span)`，`span = max(min_gap+1, round(MAX_DOWNSWING_SEC*fe))`（修复 P3）；高度判据改用 `h`；窗口内无回落穿越时回退速度峰。
- **`segment_swing` / `_cli`**：透传 `aspect`。

## 8. 遗留问题

1. **2 段残缺视频诚实 `NO_SWING`（DTL-087d40a0 / DTL-707fb04a）**
   两段视频均从挥杆中途开始（首帧手位已高举，h≈3.2 / 2.2），无 Address 阶段，Address→Top 间距≈0。属**数据源缺陷**而非算法 bug。MVP 正确识别并拒绝（返回友好文案），**不应**强行调阈值迁就。建议：产品层引导用户「从站位开始拍摄完整挥杆」。

2. **正面2 绝对时长偏长（上杆 3.17s / 下杆 1.07s）**
   经核查为慢动作或极慢挥杆视频，绝对时长被拉伸，但 8 阶段顺序正确、impact 落在「手位回到 Address 高度」语义点。MVP 阈值按实时挥杆标定，对慢动作视频的绝对时长不精确（相对顺序正确）。如需支持慢动作，应增加 fps/时长归一化，本期不在范围内。

3. **DTL 机位 X-Factor / 肩转偏大（如 470057ac=67.5°）**
   DTL 下双肩与光轴近似共线、投影肩宽被压缩，肩转/髋转的绝对数值偏大，且与正面机位朝向耦合（707fb04a 因球手朝向相反出现负 `shoulder_turn`）。MVP 设计仅支持**正面机位 + 右手球手**，`TARGET_DIR_X=+1`、`ROTATION_SIGN=-1` 已注明此限制。DTL 视频的指标仅供参考，建议后续按机位分别校准参考系。

4. **参考区间偏「良好挥杆」，业余样本普遍偏低**
   正面 3 段 Top `shoulder_turn` 为 27~66°（参考区间 70~88°），多为业余球手真实特征。指标算法正确，但 `reference.py` 的区间可能需要按用户群体（业余为主）重新标定。本期未改 `reference.py`。
