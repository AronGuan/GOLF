## 一、为什么必须要新素材（实测证据）

### 1. GolfPose HRNet-w48 关键点在现有素材上不可用

对横屏 DTL 视频 `1446d1b95c4329272f1818d6990f3c4f.mp4`（1280×720 / 30fps / 238 帧）
密集采样 frame 0~80，四种杆身方向口径的稳定性：

| 口径 | std | 帧间差 median | 帧间差 max |
|---|---|---|---|
| shaft→hosel（方案 A 候选） | 30.4° | 21.6° | 44.6° |
| hosel→heel | 26.6° | 12.8° | 57.9° |
| shaft→heel | 27.5° | 26.2° | 63.7° |
| PCA 主方向 | 26.7° | 19.4° | 42.9° |

**四口径全部不稳定**（std ≥ 26°）。真实挥杆在 4 帧间隔内杆身角度不可能变 20°+。

### 2. 根因：模型对"shaft"杆身中段没有视觉锚点

关键帧质量数据（`diag_club_quality.py` 产出 `club_quality.png`）：

| 帧 | bbox 分 | 骨架长 | shaft→hosel 基线 | kp 最低分 | 诊断 |
|---|---|---|---|---|---|
| 0 | 0.699 | 215.2 | 192.1 | **0.14** | 5 点挤在杆头附近 |
| 4 | 0.837 | 241.8 | **3.8** | 0.25 | shaft/hosel 近乎重合 → 角度 90° 噪声 |
| 24 | 0.412 | 192.8 | 154.4 | **0.11** | shaft 点预测失败 |
| 28 | 0.663 | 225.8 | 181.6 | **0.10** | shaft 点预测失败 |
| 32 | 0.456 | 266.4 | 236.0 | 0.26 | — |
| 48 | 0.827 | 478.6 | 202.0 | **0.16** | bbox 异常大（疑似误检） |
| **56** | **0.923** | 186.8 | 162.9 | **0.58** | ✅ **唯一可用** |

**7 个检出帧里只有 1 帧（F56）的 5 点全部 ≥ 0.30。**

结论：GolfPose 训练数据偏向**静态 close-up 教学片段**，真实挥杆的中段/动态段
模型域差异巨大。要么补域内素材微调，要么换模型。

### 3. 现有素材的切分也不可信（雪上加霜）

| 问题 | 实测 |
|---|---|
| SwingNet 失效 | 横屏 DTL impact conf = **0.028 / 0.077**（< 0.30 阈值）→ 回退规则引擎 |
| 规则引擎 DTL 切不出 | `NO_SWING: address->top too short: 1 < 9` |
| 切分产物错误 | address=5 / top=24 / finish=41（238 帧视频挥杆在前 41 帧） |
| 代理值偏离常理 | top = 39.4°（参考区间 55~65°） |

**现有 2 段素材不能作为定量验证数据源。**

## 三、拍摄规范

### 3.1 机位（DTL / down-the-line）

```
        ↑ 目标线（球飞出的方向）
        |
        |
   球手 ●---→ 相机光轴垂直于目标线
        |
        |
      相机（距球手 2~3 m）
```

- 相机光轴**垂直于目标线**，与球手**同高或略低于肩**
- 球手**右肩侧朝向镜头**（右手球手）
- 手机**竖持固定**（三脚架），保持水平不倾斜
- 距离 **2~3 米**

### 3.2 画面要求

- ✅ **全身入镜**：头顶、双脚、球杆全程不出画
- ✅ **球杆清晰可见**：杆身与背景有对比度，避免深色杆 + 深色背景
- ✅ **背景简洁**：避免人群、树木晃动、强反光
- ❌ 禁止：横拍、手持晃动、逆光、镜头中途移动

### 3.3 技术参数

| 参数 | 要求 |
|---|---|
| 分辨率 | ≥ 1280×720（推荐 1920×1080） |
| 帧率 | **≥ 60fps**；涉及击球段分析时 **推荐 120fps**（依据见 3.5） |
| 时长 | 4~10 秒（覆盖完整一次挥杆 + 前后各 0.5s 静止） |
| 格式 | MP4（H.264） |
| 大小 | ≤ 40MB |
| EXIF Orientation | 必须为 0（后端会拒绝非 0） |

### 3.4 动作要求

- 只拍**一次完整挥杆**（address → finish）
- 起手前**静止 1 秒**（便于定位 address 帧）
- 收杆后**保持静止 1 秒**（便于定位 finish 帧）
- 空挥或实打均可，但需在标注中注明

### 3.5 帧率为什么是硬指标（2026-09-04 实测）

帧率提高有**两个独立机制**，收益天差地别：

| 机制 | 30fps → 60fps | 收益 |
|---|---|---|
| **采样密度** | 时间量化误差 ±16.7ms → ±8.3ms | 仅改善 8.3ms，**次要** |
| **运动模糊** | 曝光 16.7ms → 8.3ms，模糊减半 | **决定性** |

关键在于第二个。假设 180° 快门（曝光 = 半帧），在横屏 DTL 素材
（`1446d1b95...mp4`，1280×720）实测：

- 手腕峰值位移 **46.0 px/帧**（MediaPipe，帧 32）
- 杠杆比 **k = 3.29**（旋转轴→握把 R=70.5px，杆长 L=161.3px）
- → 杆头峰值线速度 **4537 px/s**（151 px/帧 @30fps）

| 帧率 | 曝光 | 杆头运动模糊 | 细节衰减 |
|---|---|---|---|
| 30fps（现状） | 16.7ms | **76 px** | 119× |
| 60fps | 8.3ms | **38 px** | 55× |
| **120fps** | 4.2ms | **19 px** | 24× |
| 240fps | 2.1ms | 9.5 px | 11× |

**参照系**：慢段（address / top / finish）杆头模糊 < 5px，规则法已验证
40/40 命中。而快段 60fps 下仍有 38px —— **是慢段阈值的 7 倍以上**。

**结论**：

1. **60fps 不足以让击球段杆检测可靠**，只是从"完全不可能"变成"很勉强"。
2. 需要 **120fps 以上**才有实质改观。若手机支持（iPhone 慢动作 /
   部分安卓 120fps 模式），击球段素材务必用 120fps 拍。
3. 提高帧率**不能**修复「杆头轨迹最低点天然晚于真实击球」这一物理事实
   （见 `ADR-002-impact-frame-no-club.md` §4）—— 帧率治的是"测不到"，
   治不了"判据本身偏晚"。

复现脚本：`.workbuddy/probe_fps_impact_analysis.py`
（含人工运动模糊标定，用 Laplacian 方差量化细节衰减）

> ⚠️ **口径提醒**：细节衰减是**代理指标**，不等于真实检测率。
> 真实可检测性还取决于杆身与背景的对比度。上述结论需 120fps 素材
> 到手后实测复核。

## 四、标注格式

### 4.1 目录结构

```
data/club_videos/
├── raw/                          # 原始视频
│   ├── dtl_001.mp4
│   ├── dtl_002.mp4
│   └── ...
├── annotations/
│   ├── club_keypoints.json       # 球杆 5 点标注
│   └── phase_frames.json         # 8 阶段真值帧
└── README.md                     # 素材元信息
```

### 4.2 球杆 5 点标注（`club_keypoints.json`）

采用 COCO keypoints 格式：

```json
{
  "videos": [
    {
      "file_name": "dtl_001.mp4",
      "width": 1280,
      "height": 720,
      "fps": 30,
      "golfer_id": "g01",
      "club_type": "driver",
      "lighting": "indoor",
      "is_real_shot": true
    }
  ],
  "annotations": [
    {
      "file_name": "dtl_001.mp4",
      "frame_index": 56,
      "phase": "top",
      "bbox": [258.6, 202.1, 472.7, 267.4],
      "keypoints": [
        320.5, 245.0, 2,      // 0 shaft      (x, y, visibility)
        388.2, 232.1, 2,      // 1 hosel
        430.8, 226.4, 2,      // 2 heel
        455.1, 240.7, 2,      // 3 toe_down
        449.3, 214.9, 2       // 4 toe_up
      ]
    }
  ]
}
```

`visibility` 语义（COCO 标准）：
- `0` = 未标注
- `1` = 标注但被遮挡
- `2` = 标注且清晰可见

> ⚠️ **只标注肉眼能明确判断的点**，判断不了的标 `1` 或直接跳过该帧 ——
> 宁可少标，不可乱标（噪声标注比没有标注更糟）。

### 4.3 8 阶段真值帧（`phase_frames.json`）

```json
{
  "dtl_001.mp4": {
    "address": 12,
    "takeaway": 28,
    "backswing": 41,
    "top": 56,
    "downswing": 68,
    "impact": 79,
    "follow_through": 95,
    "finish": 120
  }
}
```

阶段定义（GolfDB 8 事件标准）：

| # | 阶段 | 判定依据 |
|---|---|---|
| ① | Address | 杆头静止在球后，准备完成 |
| ② | Takeaway | 杆头开始后移，杆身刚离开起始位置 |
| ③ | Backswing | 杆身与地面平行（上杆中段） |
| ④ | Top | 上杆最高点，杆头速度归零的瞬间 |
| ⑤ | Downswing | 杆身再次与地面平行（下杆中段） |
| ⑥ | Impact | 杆头接触球的瞬间 |
| ⑦ | Follow-through | 击球后杆身第三次与地面平行 |
| ⑧ | Finish | 收杆完成，动作静止 |

4. 导出 COCO Keypoints 1.0 格式


> ⚠️ **2026-09-04 口径更新**：验收目标从「ONNX 门控放行率」改为
> 「**端到端真值化覆盖率**」。因为现在真值源是**规则法优先**，
> ONNX 只是次要源；只看 ONNX 放行率会严重低估系统真实能力。

| 验收项 | 目标 | 当前基线（2 段现有素材） |
|---|---|---|
| 视频数量 | ≥ 20 段 DTL | ❌ 2 段 |
| 切分成功率 | 100%（不应有 NO_SWING） | ⚠️ 横屏可切 / 竖屏靠回退 |
| SwingNet impact conf | ≥ 0.30（或明确回退但规则引擎能切出） | ❌ 0.028 / 0.077 |
| **端到端真值化覆盖率**（`source=measured` 的阶段占比） | **≥ 80%** | 🟡 横屏 3/3，竖屏 1/3 → 4/6 = 67% |
| 关键帧 top 命中率 | **100%**（top 是 swing_plane 唯一取值点） | 🟡 1/2（竖屏未命中） |
| 规则法置信度 ≥ 0.30 占比 | ≥ 80% | 🟡 横屏 0.77/0.54/0.66 全过 |
| 真值 vs 参考区间 | top 应落在 55~65° | 🟡 53.5°（横屏，差 1.5°） |
| ONNX 门控放行率（次要指标） | ≥ 60% | ❌ **5%**（1/20） |

**最小验收门槛**：只要「端到端真值化覆盖率 ≥ 80%」且「top 命中率 100%」，
素材即视为合格，ONNX 放行率不达标不再阻塞。

### 规则法真值源的关键设计（务必保留，勿回退）

在 `club_probe._observe_rule` 中，有三处**反直觉但必要**的设计，
是修复"级联失效"的核心，改动前请先重跑 `quant_rule_vs_onnx.py`：

1. **锚点只用 8 个事件帧，不做窗口扩展**
   - `plan_frames` 的密集窗口 + 速度门控会让单帧失败逐级传染
   - 实测：F5 成功（conf 0.649）→ F14 失败 → `last_dir` 冻结在 76.5° → F17~F37 全挂（含 top）
2. **强制走 `_detect_hough`，禁用帧差通道**
   - 事件帧间隔大（几帧到几十帧），帧差法失效
3. **扇形搜索角从默认放宽到 35°**（`CLUB_RULE_FAN_DEG`）
   - 事件帧之间杆身可大幅转动，默认窄扇形搜不到
